# Project YI — 이순신 생애·세계사 연표·난중일기 아카이브

기획 근거: `crosscheck-2026-11-15.md` (ChatGPT/Gemini/Claude 3회차 교차검증).
기준 판본: **교감본(노승석)**. 첫 산출물: **1597년 MVP 스키마와 샘플 데이터**.

## 명령
```bash
npm run validate   # 샘플 데이터 검증
npm test           # 단위 테스트 (Node 18+)
npm run serve      # MVP 화면: http://127.0.0.1:5173/ (연표·사료 층위·판본/일기)
```

## 일기 원문 입력 흐름
1. `data/input/gyogam-1597.tsv`에 하루 한 줄로 입력한다 (열: `lunar_month, lunar_day, leap, gregorian, text_han, text_ko, source_ref, note`). 헤더와 주석만 있는 빈 템플릿이 들어 있다.
2. 미리 확인: `node tools/import_diary.mjs data/input/gyogam-1597.tsv data/sample/nanjung --year 1597 --by <입력자> --dry`
3. 오류가 하나도 없을 때만 저장된다. 같은 id는 교체, 나머지는 유지. 월별 입력 일수가 출력된다.
4. `npm run validate`로 최종 확인.

**국가유산포털 원문 가져오기(초고본 5책·6책)**: `node tools/research/fetch_heritage_text.mjs <책>` → `node tools/research/build_diary_tsv.mjs <책> <시작 음력 월> <출력.tsv> <시작 일>` → `node tools/import_diary.mjs <tsv> data/sample/nanjung --year 1597 --by <이름> --edition ed-autograph --reading rd-heritage-portal --volume "<책 이름>" --tag <b5|b6>`. 5책은 시작 `4 … 1`, 6책은 `8 … 6`(8/4~8/5는 훼손 단편이라 8/6부터). 월 머리(`九月初一日…`)가 있으면 롤오버 추정보다 우선하고, 무술년(1598) 정월 이후는 1597 입력에서 제외한다. 같은 날짜가 여러 책에 있어 항목은 `volume`으로 구분한다. 포털은 펼침면(2쪽) 단위로 응답하므로 중복 면을 제거하고, 날짜 번호를 기준으로 일별 분할한다. 포털 판독문은 미검수이며 이용 조건(공공누리 유형)을 확인하기 전에는 공개 배포하지 않는다.

**세계 트랙(`track: "world"`, 40건)**: 이순신의 삶(1545~1598) 동안의 세계 사건을 지역(`region`: 임진왜란 전반·동아시아·유럽·세계 교역/달력)으로 나누고 이순신·전쟁과의 연결을 맥락(`connection`, 인과 주장 아님)과 관련 항목(`relates_to`: 사건·일기 항목 id)으로 적는다. 화면은 「세계 연표」 탭(전체 표·지역 필터)과 연도별 연표의 '세계' 레인. 검증기 규칙: 세계 사건은 `region`·`source_ids` 필수, `relates_to` 대상 존재, 율리우스/그레고리 원본 표기와 날짜 필드의 일치(1500-03-11~1700-02-28은 −10일 환산, 1582 이전 사건 지원). 전부 2차 출처의 `unverified`이며 작성 원칙·교정 기록은 `docs/world-track.md`.

**외부 기록 근거(`records.json`, 선조실록)**: 세계 사건의 날짜를 한국 사료로 확정하는 근거 기록. 실록 기사의 헤더(권·음력 날짜·**일간지**)로 날짜를 일기와 같은 방식으로 확정하고, 사건 날짜의 근거가 되는 짧은 원문 인용(≤125자)과 우리 요약(`statements`)만 담는다(한국고전번역원 국역과 전문은 수록하지 않음). 사건은 `date.basis_records`로 기록·인용을 가리키며, 검증기가 ① 기록 헤더 일간지가 달력과 맞는지, ② 인용된 음력 날짜에서 도출한 양력(같은 달이면 기록일±일수, 다른 달이면 일간지로 확정된 일기 항목으로 연결)이 사건 날짜와 같은지 확인한다. 세계 사건을 `verified`로 올리려면 일기 또는 이 근거가 필요하다. 현재 26건의 기사로 사건 10건(노량해전 포함, 평양 수복, 행주 전투, 가토 다대포 도착, 한성 일본군 철수, 2차 진주성, 남원성, 히데요시 사망 풍문 보고, 울산·순천 일본군 철수)의 날짜를 확정하고, 이순신 트랙에 조정의 전사 언급 1건을 추가했다. 히데요시 사망일은 실록에 서로 다른 진술(7/7·8/18)만 있어 확정하지 못했다. 상세와 한계는 `docs/world-track.md`.

**판독 쟁점 카드(`reading_issues.json`)**: 같은 글자를 두고 판독·해석이 갈리는 대목을 카드로 만든다(화면의 「판독 쟁점」 탭). 카드는 ① 출현 위치(일기 항목 id, 포털 판독 글자, 문맥), ② 읽기 비교(`observed`=우리 판독문에서 관찰, `claim`=특정인의 주장), ③ 해석(뜻풀이), ④ 수용사, ⑤ 우리 데이터에서 확인한 사실, ⑥ 확정하려면 할 일로 이루어진다. 규칙(검증기가 강제): 출현 위치의 글자·문맥은 실제 일기 본문에 있어야 하고, **주장·해석·수용사의 주장에는 출처(source_ids)가 반드시 붙어야 하며**, 이 프로젝트는 어느 쪽도 판정하지 않는다(`status: unresolved`). 현재 2장: 4책 9월의 `女眞`(ri-1596-yeojin)과 9/11의 `歲山月`/`萊山月`(ri-1596-naesanwol). 출처가 언론 보도 위주라 전문 재확인이 필요하다.

**1~3책(1592~1594)**: 책 모양이 4~7책과 달라 분할기에 옵션을 더했다. 2책은 `build_diary_tsv.mjs 2 5 <tsv> 1 --tail-cut 十五日一`(9/15는 머리만 있고 뒤는 어제시·장계 초안류), 3책은 `build_diary_tsv.mjs 3 1 <tsv> 1`로 분할한다(1594 1/1~11/28; 포털 해제문 목록의 '7월 28일'은 오기로 보임). 1책은 한 책 안에서 연·월·형식이 구간마다 달라서 `--segments data/input/heritage/segments-book1.json`로 구간(앵커 문자열)을 지정하고 `--only 1592`/`--only 1593`으로 해별로 따로 가져온다. 구간 A(1592 5~8월 19일)는 일간지가 없어 `noGanji`(날짜는 월·일 표기와 변환기 기준, `unverified`), 구간 B(1593 2월 1일~3월 20일)는 일간지가 있어 전부 `verified`이다. 구간 B는 판독문의 월 표기('二月')가 일간지와 맞지 않아 `ignoreMonthHeader`로 월 머리를 무시하고 일간지가 가리키는 달(2월·3월)로 배정했다. 일간지 가운데 괄호 글자('癸(未)卯')는 괄호를 뺀 글자로 읽고 원표기를 `note`에 남긴다. 일기 본문 뒤의 장계 초안·감결·장부류는 일기가 아니므로 입력하지 않는다.

**1596년 일기(4책 병신일기)**: `node tools/research/fetch_heritage_text.mjs 4` → `build_diary_tsv.mjs 4 1 <tsv> 1 --tail-cut 十月初九日` → `import_diary.mjs <tsv> data/sample/nanjung --year 1596 ... --volume "4책 병신일기" --tag b4`. 1596년에는 윤8월이 있어 월 머리의 `閏八月初一日…`을 읽어 `leap` 열(`1`)로 내보내고, 항목 id는 `…-1596-L08-01`처럼 윤달을 `L`로 표기한다. 책 끝(10/11 뒤)의 장부 메모는 `--tail-cut`으로 일기 본문에서 떼고, 포털 판독문의 주석 번호(`1)` 등)와 면 라벨(`빈면`·`표지`)은 분할기가 제거한다. 305일 전부 일간지가 달력·변환기와 일치한다.

**1598년 일기**: 6책 끝의 정월 1~4일은 `build_diary_tsv.mjs 6 8 <tsv> 6 --only 1598`, 7책 무술일기(9/15~10/7)는 `build_diary_tsv.mjs 7 9 <tsv> 15 --only 1598`로 분할하고 `--year 1598`(`--volume "7책 무술일기" --tag b7`)로 가져온다. 27일 전부 일간지가 달력·변환기와 일치(`verified`)한다. 7책 앞부분의 명 장수 선물 목록과 10/7 항목 끝의 명 보고문·선박 수 목록은 일기 본문이 아니므로 분석 전에 분리해야 한다(결측 기록 참조). 현존 초고본에는 1598 1/5~9/14와 10/8~11/18의 일기가 없다.

**일간지 불일치(`ganji_check`)**: 일기에 적힌 간지가 변환값 ±3일의 어떤 날과도 맞지 않으면 거부하지 않고 `certainty: disputed`와 `ganji_check`(적힌 값, 기대값, 천간 일치, 지지 이동)로 기록한다. 이때 양력은 천간이 맞는 날(변환값 ±1일)을 우선한다. 1597년 5책은 7/4~10/3에서 천간은 맞고 지지가 일관되게 +2라 이 경로를 탄다.

**일간지(`day_ganji`)**: 일기 날짜 머리의 일간지를 적으면 양력이 확정된다(`certainty: verified`). 입력 양력과 어긋나거나 변환값 ±3일 안에 없으면 거부되고, 검증기도 저장된 양력과 일간지가 다르면 오류로 잡는다. 일간지는 달력 개혁·역법 차이와 무관해 변환기보다 우선한다. 명량 9/16이면 甲辰=10/26, 癸卯=10/25.

규칙: `text_han`(한문 판독문)이 분석 대상이고 `source_ref`(교감본 쪽수 등)는 필수. 입력 직후 상태는 `transcribed`/`unverified`이며, `reviewed`는 `reviewed_by`가 있어야 한다. 입력된 날이 없는 날은 "사건 없음"이 아니라 "입력되지 않음"이다.

**저작권 주의**: 한문 원문은 공유 재산이지만 교감본의 교감 결과와 한글 번역은 노승석 등의 저작물일 수 있다. 사용 허락을 확인하기 전에는 `text_ko`를 비우고, 한문은 입력자가 직접 판독·대조한 것만 넣는다. `text_ko`를 채우면 `--translator`가 필요하다.

## 구조
- `data/schema/schema.json` — 데이터 모델 (Source, Event, Claim, Edition, Reading, DiaryEntry, Coverage, DateRecord)
- `data/sample/nanjung/*.json` — 난중일기 샘플 데이터 (현재 1596~1598년. 1592년까지 확장할 예정이라 연도 없는 이름을 쓴다)
- `tools/validate.mjs` — 스키마·참조 무결성·날짜 일관성 검증

## 설계 원칙
1. **날짜**: 원본 달력 표기(음력·윤달 여부)를 보존하고 그레고리/율리우스 값은 따로 저장한다. 율리우스력은 그레고리력 -10일(검증기가 확인).
   - **음력→양력**은 `korean-lunar-calendar@0.4.0`(`tools/lunar.mjs`)으로 계산하되 **사료 날짜를 덮어쓰지 않는다.** 입력값과 계산값이 다르면 `certainty: disputed`로 두고 `computed_gregorian`에 계산값을 병기한다(검증기가 강제). 이 표는 현대 기준이라 16세기 조선 역법과 월 경계가 하루 어긋날 수 있다. 실제로 명량(음력 1597-9-16)은 문서의 양력 10-26과 변환기의 10-25가 다르다. 조사 결과 변환기 표 오류 가능성이 높으나 확정은 아니다(아래 다음 단계 2번).
   - 기준점 4건(1545-3-8, 1592-4-13, 1592-7-8, 1598-11-19)은 문서 값과 일치해 테스트에 고정했다.
2. **검증 상태**: 모든 연표 항목은 `verified: false`, `certainty: unverified`로 시작한다. 원문 대조 후에만 올린다.
3. **출처별로 갈리는 수치**는 `claims.json`에 병기한다 (예: 명량의 일본 함선 수).
4. **결측**은 `coverage.json`으로 "기록 안 됨/결락"과 "사건 없음"을 구분한다.
5. **판본·판독 분리**: DiaryEntry는 `edition_id`와 `reading_id`를 함께 가진다. 분석은 한문(`text_han`), 번역(`text_ko`)은 표시용.
6. **본문 미생성**: 난중일기 본문은 교감본 원문을 입력하기 전까지 `placeholder`로 둔다.
